# 2026-09-21 adoption 확대 실험

2모델 × 8과제 × with/without × 2회, 총 **64회**를 완료했다. with 조건에서
실제 도구를 사용한 런은 Haiku **12/16(75%)**, Sonnet **7/16(43.75%)**였다.
without의 실제 dartograph 호출은 **0/32**다. CLI가 보고한 비용 합계는
**$7.24270565**이며 실제 청구액이 아니라 각 실행의 `total_cost_usd` 합계다.

과제·조건별 n=2이고 자동 채점에도 확인된 한계가 있다. 이 결과로 일반적인
정확도나 속도 향상을 주장하지 않는다. [방법론](../AGENT-BENCHMARK.md)과
[기계 판독 집계](adoption-20260921.json)를 함께 읽는다.

## 원시 기록 보정과 검증

기존 판별식 `\bdartograph\b`가 `dartograph-benchmark`라는 디렉터리를
grep하는 명령도 도구 호출로 셌다. 명령 위치·일반적인 wrapper·MCP 호출을
구분하는 `command-position-v1`으로 **64개 원문을 재집계**했다.
호출수가 바뀐 기록은 **34개**, 경로 오탐으로 붙었던 without 오염 표시는
**23개**다. 원래 원장·transcript·정답 채점·비용은 덮어쓰지 않았다.

새 회귀 테스트는 이 grep 입력에서 수정 전 예상 0/관측 1로 실패했고, 수정
후 통과했다. 재집계 도구는 원본을 읽기만 하며 누락된 transcript를 호출 0으로
바꾸지 않는다. 동적 eval 등 임의의 shell을 완전히 해석하는 판별기는 아니므로
이번 64개 기록의 Bash·MCP 입력을 별도로 감사했다. 실제 실행 누락이나
without의 도구 호출은 발견하지 못했다.

후속 GLM 리뷰에서 wrapper의 값 인자, 소스 체크아웃의 Dart 실행과 heredoc
경계를 보완한 `command-position-v2`로도 같은 원문을 재집계했다. 64개 기록의
사용량·오염 판정과 나머지 지표는 v1과 같았다. 본 집계 JSON은 당시 v1 결과를
보존하며, 로컬 `corrected-v2-{haiku,sonnet}/`에 후속 검증본이 있다.

실행 뒤 6개 checkout의 Dart 소스·pubspec·lockfile 해시가 준비 시점과
같음을 확인했다. with 32개 세션은 MCP connected, without 32개 세션과
관찰된 하위 세션은 MCP 서버가 없었다. CLI가 표시한 6개 auto-memory
디렉터리는 파일이 0개였다. `haiku / inv-dead / without / run 1`은 같은
Haiku 모델의 하위 에이전트를 1회 사용했다. 하위 이벤트도 원문에 보존했다.

## 채점 감사와 실패

사전 정의한 기대 문자열과 자동 채점은 바꾸지 않았다. `nav-dead`·`nav-impact`
16개와 `inv-dead` 8개, 총 **24개 답변 기록**을 소스와 대조했다.

- `nav-impact` without 4개는 세 익명 `GoRoute.builder`와 정확한 호출 경로를
  찾았으나 `_BookstoreState` 문자열이 없어 오답 처리됐다. 자동 점수의 상승을
  실제 호출자 발견의 개선으로 해석할 수 없다. 이 중 Sonnet run 0에는 추가로
  설명한 downstream 파일 이름 오류(`book_details_screen.dart`)도 있었다.
- 정상 `inv-dead` 답변 7개는 기대한 두 멤버를 포함했다. 그러나 without 답변
  3개(Haiku run 1, Sonnet run 0·1)는 `hashCode`·`toString`도 dead로 추가했다.
  직접 참조를 찾지 못했다는 사실만으로 override의 암시적 호출까지 부재하다고
  증명할 수 없으며, 현재 문자열 채점은 이런 추가 주장을 감점하지 않는다.
- `haiku / nav-dead / with / run 0`은 삭제해도 안전하다는 표현을 썼다.
  이는 dartograph의 도달성 근거를 넘어선 에이전트의 과잉 주장이다.
- `sonnet / inv-dead / with / run 1`은 도구를 사용하지 않은 채 18턴 뒤
  `error_max_budget_usd`로 종료됐다. 보고 비용은 **$0.522731**다. $0.50
  설정은 진행 중인 API 요청 비용만큼 초과할 수 있으며, 이 실패를 재실행하거나
  정상 답변으로 세지 않았다.

## 실행 조건과 재현

- 모델 ID: `claude-haiku-4-5-20251001`, `claude-sonnet-5`. 실제 assistant
  응답의 모델 ID도 init과 일치했다.
- dartograph 0.15.0 고정 바이너리, Dart 3.13.3, 공개 저장소의 핀 리비전과
  과제는 [tasks.json](../../tool/agent_benchmark/tasks.json)을 사용했다.
- 대상 SDK 준비·소스 일치·사전 MCP 질의는 [환경 기록](../AGENT-BENCHMARK.md)에
  있다. 사전 질의로 분석 캐시가 채워졌으며 cold 인덱싱 실험이 아니다.
- 첫 Haiku 대조군으로 한도 회복을 확인한 뒤 두 모델을 병행했다. 모델 안에서는
  run마다 without/with를 교번했다. 두 모델은 checkout과 캐시를 공유하므로
  시간 값에 동시 실행의 영향이 있을 수 있다.
- 앞선 연결 파일럿 2회는 주간 한도로 실패했고 비용 $0이었다. 본 실험과
  합쳐 승인된 논리적 실행은 66회이며 추가 모델 재실행은 하지 않았다.

원본은 로컬 `.git/evidence-adoption-20260921/matrix-{haiku,sonnet}/`에 있다.
`corrected-{haiku,sonnet}/`는 재집계본이며, 원본·재집계본·64개 transcript의
해시는 `recount-manifest.json`에 보존했다. 재집계는 외부 모델을 호출하지 않는다.

```sh
# 원본 summary.jsonl과 모델명이 포함된 transcripts/가 있는 디렉터리
dart run tool/agent_benchmark/recount_usage.dart /path/to/results \
  > /path/to/new-summary.jsonl
```

관찰한 과제에서 도구 사용은 확인했지만, 사용하지 않은 경우와 비용·오류가
늘어난 경우도 있다. 다음 비교에서 정확도를 판단하려면 실험 전에 대체 가능한
정답 표현과 추가 오답의 처리 기준을 정하고, 삭제 안전성 과잉 주장도 따로 채점해야 한다.
