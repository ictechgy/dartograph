# 결정: 증분 분석

상태: **구현(미릴리스)** — 파일 단위 사실 캐시와 `--incremental <dir>`가
`lib/src/index/incremental_cache.dart`·`lib/src/index/analyzer_graph_index.dart`에
구현되어 색인 명령 11개에 배선됐다(브랜치 `feat/incremental-analysis`, 커밋
`00d22fa` 구현 + `941e595` 최적화). 다음 minor(0.10.0) 발행 후보이며
`doc/USAGE.md` 명령 목록에도 반영했다. 같은 P0의 **검증 원장(append-only JSONL)은
아직 미착수**다.

## 1. 문제

요구 4는 "CI에서 자동화할 만큼 빠르거나 증분"이다. 현재 분석은 매 실행마다 루트 안
전체 `.dart`를 다시 해석한다(캐시는 해석 결과가 아니라 실행 산출물 단위다). 대형
체크아웃에서 이 비용이 CI 상시 실행을 어렵게 만든다.

## 2. 결정

**파일 단위 사실 캐시 + 역방향 import 폐쇄 재해석**을 도입한다.

- 새 옵션: `--incremental <dir>`. 디렉터리는 호출자가 지정하고, 없으면 만든다.
- 캐시 단위는 **파일 하나**다. 키는 그 파일의 내용 해시 + 그 파일의 해석에 영향을 주는
  입력(설정·package config·의존 패키지 `lib`의 관련 해시·SDK 버전·도구 버전)이다.
- 실행 시:
  1. 대상 파일 집합과 각 파일의 현재 키를 계산한다.
  2. 키가 이전 실행과 같은 파일은 사실을 캐시에서 읽는다.
  3. 키가 달라진 파일 + 그 파일을 (전이적으로) import하는 파일만 다시 해석한다.
  4. 새 사실로 그래프를 재구성하고, 캐시를 원자적으로 갱신한다.

## 3. 이유

- 기존 `lib/src/index/`의 사실 추출 경로를 재사용할 수 있어 새 분석기를 만들지 않는다.
- import 폐쇄는 보수적이다. 즉 "다시 해석할 필요가 없는 파일"만 건너뛰고, 애매하면
  다시 해석한다. 놓치는 쪽보다 더 하는 쪽으로 기운다.
- 산출물은 전체 분석과 **byte 동등**해야 한다. 캐시는 속도만 바꾸고 출력은 바꾸지 않는다.

## 4. 무효화 규칙

| 입력이 바뀌면 | 무효화 범위 |
|---|---|
| 파일 내용 | 그 파일 + 역방향 import 폐쇄 |
| 루트 밖 상대 import 파일 | 그 파일을 import하는 파일(기존 캐시 키의 문서화된 경계를 계승) |
| `dartograph.yaml` `entry_points` | 보존 루트가 전역이라 **전체** |
| `pubspec.yaml`·package config·의존 패키지 `lib` | 관련 해석 입력이 바뀌므로 **전체** |
| 도구 버전 | **전체**(기존 `_cacheIdentity`와 같은 규칙) |
| SDK 버전 | **전체** |

## 5. 실패 경로

- **캐시 손상·버전 불일치**: 캐시를 무시하고 전체 분석으로 폴백한다. 오류로 끝내지
  않는다(캐시는 최적화지 계약이 아니다).
- **캐시 디렉터리 쓰기 실패**: 분석은 정상 수행하고, 캐시를 쓰지 못했다는 사실을
  limitation으로 남긴다.
- **분석 실패**: 기존 계약대로 종료 코드 2. 부분 결과로 오판을 유도하지 않는다.
- **중단(타임아웃·SIGINT)**: 임시 파일에 쓰고 rename으로 교체하므로 캐시가 반쯤
  갱신된 상태로 남지 않는다(`lib/src/core/atomic_write.dart`의 기존 경계를 재사용).

## 6. 완료 판정 기준

1. **출력 동등성**: 같은 입력에서 증분 실행과 전체 실행의 산출물이 byte 동일하다.
   `tool/benchmark_index.dart`의 7종 sha256 대조 방식을 그대로 쓴다.
2. **속도**: 동일 저장소·동일 입력에서 실측 배수를 기록한다. 목표는 전체 분석 대비 5배
   이상이고, 미달하면 실측값을 정직하게 적는다(측정 없는 최적화 금지 규칙).
3. **회귀**: 캐시 손상·버전 불일치·쓰기 실패·무효화 5종 각각에 단위 테스트가 있다.
4. **문서**: 구현 후 `doc/USAGE.md` 명령 목록과 `## 종료 코드`에 반영한다.
   (완료 — 명령 목록에 `--incremental <dir>`를 반영했다. 이 옵션은 종료 코드를 바꾸지
   않아 `## 종료 코드`에는 추가할 항목이 없다.)

## 7. 결정된 사항과 남은 미결

구현하면서 아래를 확정했다.

- **캐시 파일 형식**: 단일 JSON(`facts.json`), 압축 없음. 교체는 임시 파일 + rename
  (원자적)이라 중단돼도 이전 캐시가 남는다. 항목 하나가 손상되면 그 항목만 미스다.
- **폐쇄 경계**: import·export·part 지시문과 미해결(대상이 아직 없는) 지시문까지
  의존으로 센다. 조건부 import는 공개 analyzer가 고른 단일 구성만 보므로 기존
  `conditional-configuration` 한계를 따른다.
- **OS 캐시와의 관계**: 증분은 전체 결과 캐시를 읽지도 쓰지도 않는다. `--incremental`은
  호출자가 지정한 디렉터리에만 쓰고, 기존 OS 캐시 경로는 그대로 둔다.

남은 미결:

- 검증 원장(같은 P0 항목)과의 결합: 캐시 히트 여부를 원장에 남길지.

## 8. 되돌리기

`--incremental`은 옵션이므로 **주지 않으면 기존 경로 그대로**다. 문제가 생기면 플래그를
쓰지 않거나, 이후 릴리스에서 제거하면 된다. 캐시 디렉터리는 언제든 삭제해도 안전하다.

## 9. 구현 기록 (2026-09-15/16)

- **구현**: 커밋 `00d22fa`(Step A) + `941e595`(최적화). `--incremental <dir>`를
  색인 명령 11개가 받는다(help·USAGE 반영).
- **출력 동등성(§6-1)**: `tool/benchmark_index.dart`의 7종 산출물 sha256이 전체
  해석과 세 조건(변경 없음·널리 import되는 파일 변경·잎 파일 변경) 모두 일치한다.
- **속도(§6-2, 합성 600파일 실측)**: warm **7.5배**, leaf **1.9배**, imported
  **0.94~1.04배**. imported의 역방향 폐쇄는 사실상 전체라 해석 비용이 지배한다 —
  목표 5배 미달을 그대로 기록한다.
- **회귀(§6-3)**: 캐시 손상·버전 불일치·쓰기 실패·삭제·part·설정 변경·의존 패키지
  변경 테스트가 `test/index/incremental_analysis_test.dart`에 있다.
- **최적화(`941e595`)**: 파일 해싱 동기화, 캐시 사실 파싱을 폐쇄 계산 뒤로 지연,
  캐시가 현재 입력과 같으면 store 생략.
- **미착수**: 검증 원장(`--record` + `history`) — 같은 P0의 나머지 절반이다.
